# Phase 6 - UI Design Contract

> Visual and interaction contract for the session picker, the read-only board view and the copy buttons in the Session tasks pane. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Locked inputs: D-43 to D-46 in `06-CONTEXT.md`, the approved sketch `.planning/sketches/06-session-picker.html` (approved by Theo 2026-11-02), PANE-09, PANE-10 and PANE-13.
> This phase EXTENDS `04-UI-SPEC.md`. Every Phase 4 token, class, copy string and rule stays unless a line below says "changes". This file adds no decision that contradicts CONTEXT.md. Where the approved sketch and CONTEXT.md differ (the `0 skipped` wording, the notice position), CONTEXT.md text wins and the difference is stated in the section that sets it.

The pane stays the only screen. It gains one picker row, one menu, one banner, one extra header button, one extra row button and one longer notice. It has three states: the focused board (Phase 4, with the picker row on top), the picker open, and another session's board read only.

| Role | Value | Usage |
|------|-------|-------|

Accent reserved for: the checked state of the item `Checkbox` and the SDK focus ring. The sketch draws the Copy all open button in accent blue. 1. The banner has a 1px `border-(--ui-yellow)` and `text-(--ui-text-primary)`, with no fill. The sketch's tinted fill needs `color-mix`, which is banned. The read-only state is told by the banner text, not by colour alone.
2. The shown board in the menu is marked by an `icons.Check` and `aria-current`, not by a tinted row. The SDK focus fill shows the keyboard position.
3. Read-only rows keep the Phase 4 done style (line-through plus `var(--ui-text-secondary)`). The disabled `Checkbox` dimming is SDK-owned.
4. The Phase 3 test `test_plugin_has_no_colour_literal` stays. The Phase 4 palette-class regex stays exactly as written in `04-UI-SPEC.md` rule 4. Do not add `yellow` to it: `--ui-yellow` is a theme variable and the regex would match its `-yellow` tail. Add one check that the banner class string contains `border-(--ui-yellow)` and no other colour token.

## Copywriting Contract

Phase 4 strings stay unchanged. Strings that change are marked "changes". Every new string is listed here. A string not listed needs a change to this file.

### Kept from Phase 4 (unchanged)

`Add an item`, `Add a subtask`, `The agent adds items here.`, `Add one below.`, `Open a chat to see its items.`, `{done}/{total}` subtask count, `Board changed, showing the latest`, `Could not save that change. Try again.`, `Could not load the board. Retrying.`, `Version mismatch: update the desktop plugin on this machine`, the delete confirmation strings, the icon button labels, `Copy as markdown`.

### New strings

| Element | Copy |
|---------|------|
| Picker count (trigger and menu) | `{open} of {total} open` (the Phase 4 `headerText`). Hidden when total is 0. This replaces the Phase 4 header line (changes: the text moves from the header row into the picker row). |
| Picker trigger aria-label | `Session: {label}, {open} of {total} open`, or `Session: {label}` when total is 0 |
| Picker trigger Tip | `Choose a session` |
| Untitled name | `Untitled session` |
| Board label (single line: trigger, Copy all open, notice, Back aria-label) | The Hermes title, else `preview`, else `Untitled session {short id}` |
| Menu row name | The Hermes title, else `preview`, else `Untitled session` |
| Menu row sub-line | Parts joined with ` - `: `this session` for the focused board, then the short id for an untitled board. Absent when neither applies. Examples: `this session`, `a1f3c9`, `this session - a1f3c9`. |
| Menu row right block | Line 1: `{open} of {total} open` (absent when total is 0). Line 2: the update time (see Time labels). |
| Menu: no other boards | `No other session has a board.` (disabled item, shown under the focused row) |
| Menu: list failed | `Could not load the session list. Reopen the list to retry.` (disabled item, shown under the focused row) |
| Banner text | `Read only. Viewing another session.` |
| Banner link | Visible label `Back` (aria-label `Back to {focused label}`). The visible label is fixed by the approved sketch. |
| Header button | `Copy all open to {focused label}`. Tip text and aria-label carry the full label. Disabled when the shown board has no open item. |
| Row button | Visible label `Copy` (aria-label `Copy item to {focused label}`). The visible label is fixed by the approved sketch. |
| Read-only empty state | Title `This board is empty.` Description (next step) `Pick another session or go back.` No add line. |
| Copy notice | Always `Copied {N} to {focused label}. {M} skipped, already on the board.` including `0 skipped, already on the board.` when M is 0 (D-42). One line. |
| Copy notice, cap hit | The sentence above, then ` {K} not copied, the board holds 100 items.` (K above 0 only). Still one line. |
| Copy notice, source item gone (stale reply with reason `not_found`) | `Board changed, showing the latest` (the Phase 4 stale string; the shown board reloads) |
| Copy notice, any other failure | `Could not save that change. Try again.` (the Phase 4 write failed string) |

Notes:

1. `{short id}` is the last 6 characters of the board root id. Hermes ids look like `20261102_133806_e5cc98`, so the first 6 characters are a date and tell boards apart badly. Example: `e5cc98`.
2. The sketch notice reads `Copied 1 to Lease renewal. 0 skipped.` D-42 fixes the sentence `Copied N to <title>. M skipped, already on the board.` The contract uses the D-42 sentence in full, every time, including `0 skipped, already on the board.`. `Copied 0 to {label}. 0 skipped, already on the board.` is valid when no item copied and none skipped.
3. Singular and plural: the counts are numerals, so no word changes (`Copied 1 to`, `1 skipped`).
4. Time labels: `just now` (under 1 minute, and any future time), `{n} min ago` (1 to 59), `today {HH:mm}` (older than 1 hour, same local calendar day, 24-hour clock with zero padding, for example `today 09:12`), `{Mon} {D}` (an earlier day this year, English three-letter month, for example `Oct 30`), `{Mon} {D}, {YYYY}` (an earlier year). An unparseable or absent time shows no line. The label is computed when the menu opens and does not tick.
5. Every string is plain text. Titles and item text render as React text children, never as HTML.
6. The visible labels `Copy` and `Back` stay short, as in the approved sketch. The aria-labels carry the target (`Copy item to {focused label}`, `Back to {focused label}`); each aria-label starts with its visible label, so the accessible name contains the visible text.
7. Destructive actions in this phase: none. A copy adds items and removes nothing, so no confirm dialog. The read-only view has no delete.

## Interaction Contract

Where a line says "(D-xx)", the CONTEXT.md text wins.

### Picker row (PANE-09, D-43)

1. The picker row is the first element of the pane. It replaces the Phase 4 `N of M open` header line. It does not add a row above it.
2. It is one `Button` (`variant: 'outline'`, `size: 'sm'`, `className` with `min-h-8 w-full justify-between`) as the `DropdownMenuTrigger asChild`, wrapped in `Tip` (label `Choose a session`).
3. Inside, left to right: title `span` (14px / 500, flexible, truncates with an ellipsis), count `span` (12px / 400, `var(--ui-text-secondary)`, `shrink-0`, hidden when total is 0), `icons.ChevronDown` (`size-4 shrink-0`).
4. The trigger shows the shown board: the focused board by default, the picked board in the read-only view. Title and count follow that board.
5. With no focused chat, the picker row is not rendered. The pane shows only the Phase 4 no-chat `EmptyState`.

### Picker menu (PANE-09, D-43)

1. Content: `DropdownMenuContent` with `align: 'start'` and `style: { width: '304px' }`. It scrolls when long (SDK `overflow-y-auto`).
2. Rows, in order: the focused board first, always listed even when its board is empty. Then a `DropdownMenuSeparator`, then every other board, newest `updated_at` first. A board with no `updated_at` sorts last. Ties break by root id.
3. Each row is one `DropdownMenuItem` with `onSelect`. Layout inside: a left block (`min-w-0 flex-1`) with the row name (12px / 500, truncates) and, when present, the sub-line (12px / 400, `var(--ui-text-secondary)`); a right block (`shrink-0`, text right-aligned, 12px / 400, `var(--ui-text-secondary)`) with the count line and the time line; a 16px check slot (`size-4 shrink-0`) that holds `icons.Check` only on the shown board.
4. The shown board's row carries `aria-current: true`.
5. Selecting the focused row, or the row of the board already picked, returns to the focused board (same as Back). Selecting another row opens that board read only.
6. Data. When the menu opens, the pane calls `GET /boards` and `host.request('session.list', { limit: 200 })`, then redraws. It does not call either one on the 6000 ms poll. The `session.list` titles also load on mount and on a focus change. The last good lists stay on screen while a call is in flight.
7. Titles (D-43): join each `sessions` row to a board by `row._lineage_root_id ?? row.id` (use `??`, not `||`; the key is `null` for a session that was never compressed). Title is `row.title`, else `row.preview`, else the untitled label. A board with no row in `session.list` stays listed with the untitled label and its short id.
8. The focused row is identified by the `root_id` of the focused board reply. Before the first reply it is identified by the focused session id.
9. If `GET /boards` fails: the menu shows the focused row and one disabled item with the list failed copy. If it succeeds with no other board: one disabled item with `No other session has a board.` A failed `session.list` shows no error text: the rows keep their fallback labels.
10. Keyboard and focus are SDK-owned (arrow keys, Enter, Esc, focus return to the trigger).

### Read-only view (PANE-09, D-44)

1. Picking another board sets `picked` to its root id, saves any open edit first (the Phase 4 blur-saves rule), and loads `GET /board?session_id=<root id>`. The focused board's add-line text, subtask lines and pending writes stay in memory and come back on Back.
2. The view shows, top to bottom: picker row (picked board), banner, header row, notice, list.
3. Banner: one line, `Read only. Viewing another session.` on the left, `Back` on the right. `Back` is `Button` `variant: 'text'`, `size: 'inline'`, with `className: 'underline'`. It returns to the focused board and reloads it at once.
4. Header row, right-aligned group: the `Copy all open to {focused label}` button, then the Phase 4 `CopyButton` icon. The button label truncates with an ellipsis; the icon never shrinks. The `CopyButton` copies the shown (picked) board with the Phase 4 markdown format (D-44).
5. List: the picked board's items as read-only rows (Spacing Scale). The checkbox is rendered `disabled`. Item text is a plain `span`: a click does nothing, there is no edit. No add line, no subtask add line, no plus, no trash, no `ConfirmDialog`. Chevron collapse and the `{done}/{total}` count still work, because collapse changes the view only.
6. Collapse state of the picked board lives in its own map, keyed by item id, empty at each pick. It never shares the focused board's map, because item ids repeat across boards.
7. An empty picked board shows `EmptyState` with the title `This board is empty.` and the description `Pick another session or go back.` The header `CopyButton` and Copy all open are disabled.
8. A picked board that cannot load shows the Phase 4 load failed notice and retries on the poll.
9. When the focused session changes, the pane returns to the focused board: `picked` clears, the picked board state drops, the Phase 4 reset runs (D-45).

### Copy (PANE-10, D-44, D-46)

1. Copy on a top-level row copies that item and its open subtasks. Copy all open copies every open item. Both act on the focused board and leave the picked board unchanged.
2. Row Copy button: shown on every top-level row of the read-only view, checked or not. Same reveal as the Phase 4 plus and trash buttons: `opacity-0 group-hover:opacity-100 group-focus-within:opacity-100`, space always kept, so the row never reflows. Subtask rows have no Copy button.
3. Request: `POST /board/copy` with `{ session_id: <focused sid>, from_session_id: <picked root id>, item_ids: [<id>] (row Copy only), base_rev: <newest accepted rev of the focused board, or 0> }`. Copy all open omits `item_ids`. The pane sends no other field.
4. The request runs through the same one-at-a-time write queue as Phase 4 writes, and counts as a write in flight, so a reload reply cannot undo it. A copy is not retried on any outcome, because a copy is not idempotent.
5. While a copy is in flight, every Copy button and Copy all open are disabled.
6. Reply handling:
   - `ok: true`: take the reply board as the focused board (`take(focused, reply)`), then show the copy notice from `copied`, `skipped` and `overflow`. The pane stays on the read-only view.
   - `ok: false`, `error: "stale"` (source item gone): take the returned board, reload the picked board, show the stale notice. No retry.
   - `ok: false`, any other error, or a thrown error: reload the focused board, show the write failed notice.
7. Copy never marks anything checked or edited on the picked board. The copied items show on the focused board when Theo goes Back.

### Live update and poll (D-45)

1. `ctx.onEvent('plugin.hermes-session-tasks.board.updated', ...)` reads `event.payload.root_id`. When it equals the root of the shown board (the picked root, or the focused reply `root_id`), the pane reloads the shown board. When it is a different root, the pane does nothing. When the payload or the shown root is missing, the pane reloads the shown board (the safe default).
2. The 6000 ms `POLL_MS` poll reloads the shown board and is the fallback for every other case. It stays on while a picked board is shown.
3. The Phase 4 reload rules apply to the picked board too: a reply with a rev below the newest accepted rev of that board is dropped; a reload never resets collapse state.
4. Going Back reloads the focused board at once. The focused board is not reloaded in the background while another board is shown.

### Notice line

Phase 4 rules stay: one line under the header hairline, 12px, `var(--ui-text-secondary)`, one message at a time, priority version mismatch, write failed, then the latest of stale or copied, then load failed.

The copied notice reuses this line unchanged: same position, size, colour, priority and clearing rule. It differs only in its content, and it stays on one line (D-44: "the one-line notice from D-34").

1. Duration is the Phase 4 notice duration, 4000 ms, set with `ctx.setTimeout`. It replaces any notice that shows and is replaced by the next notice.
2. The text is always `Copied {N} to {focused label}. {M} skipped, already on the board.` (D-42), with `0 skipped` when M is 0. The cap clause follows only when K is above 0.
3. The line is built from three inline pieces so the counts stay visible. The line keeps the Phase 4 style (`whiteSpace: 'nowrap'`, `overflow: 'hidden'`, `textOverflow: 'ellipsis'`) and becomes a flex row (`display: 'flex'`).
   - Head `Copied {N} to ` with `shrink-0`.
   - Title (the focused label) with `minWidth: 0`, `overflow: 'hidden'`, `textOverflow: 'ellipsis'`, `whiteSpace: 'nowrap'`. It is the only piece that shrinks, so only the title part truncates with an ellipsis.
   - Tail `. {M} skipped, already on the board.` (plus the cap clause when present) with `shrink-0`.
4. The full sentence is also set as the `title` attribute of the line, so a fully truncated title can still be read on hover.

### Registration

Unchanged from Phase 4: id `pane`, title `Session tasks`, width `320px`, placement right.

## 320 px Width Check

The pane is 320px. The picker trigger is 304px (8px pane padding each side). The figures below use an average glyph width of 6.2px at 12px and 7.2px at 14px, so they are estimates; the structural rules after the table are what the pane tests assert.

| Element | Arithmetic | Result |
|---------|-----------|--------|
| Picker trigger inner width | 304 - 20 (SDK `px-2.5` both sides) - 12 (two `gap-1.5` gaps) - 16 (caret, `size-4`) | 256px for title and count |
| Typical count `3 of 5 open` (11 characters) | about 68px | title gets about 188px, about 26 characters at 14px |
| Worst count `100 of 100 open` (15 characters) | about 93px | title gets about 163px, about 22 characters at 14px |
| Title longer than its space | `overflow: hidden`, `textOverflow: 'ellipsis'`, `whiteSpace: 'nowrap'`, `minWidth: 0` | ends with an ellipsis; the count and caret stay in place |
| Count | `shrink-0`, `whiteSpace: 'nowrap'` | never wraps and never shrinks |
| Menu row (304px) | 304 - 16 (item padding) - 16 (check slot) - 16 (two gaps) - 93 (worst count block) | about 163px for name; the name truncates, the right block does not |
| Copy all open (header row) | 304 - 24 (`CopyButton` icon) - 8 (gap) - 20 (button padding) | about 252px for the label, about 40 characters at 12px; a longer label ends with an ellipsis |
| Copied notice (one line) | 304 - about 74 (head `Copied 1 to `) - about 211 (tail `. 0 skipped, already on the board.`) | about 19px for the title, so a long title shows as an ellipsis and the counts stay visible; the full sentence is in the `title` attribute |
| Top-level read-only row | 304 - 16 (list padding) - 24 (chevron) - 24 (checkbox) - 4 - 4 - 46 (Copy button) | about 186px for text and subtask count; text wraps, as in Phase 4 |

Structural rules the harness asserts (it cannot measure pixels):

1. The picker title `span` carries `overflow: hidden`, `textOverflow: ellipsis`, `whiteSpace: nowrap` and `minWidth: 0`, and is the only flexible child of the trigger.
2. The picker count `span` carries `shrink-0` and `whiteSpace: nowrap`.
3. The menu row name carries the same truncation style; the right block carries `shrink-0` and `whiteSpace: nowrap`.
4. The Copy all open label `span` carries the truncation style, and the button carries `min-w-0`.
5. A 60 character title, a 10 character title and an empty title all render one-line trigger text.
6. The copied notice renders head, title and tail as three pieces; only the title piece carries the truncation style, and the head and tail carry `shrink-0`.

A live check on the Mac with a 60 character title and a `100 of 100 open` board confirms the estimates (06-RESEARCH.md lists one human visual check for this phase).

## Defaults Chosen By This Spec

CONTEXT.md and the sketch left these values open or differ on them. The spec took the Phase 4 precedent, the research recommendation, the SDK default, or the source named in the item.

1. Picker component is `DropdownMenu` with a `Button` trigger (Claude's Discretion in CONTEXT.md; kanban `board-switcher.tsx` precedent).
2. The focused board is pinned first in the menu; the others sort newest first. D-43 orders boards newest first and says the focused session is always listed; the approved sketch pins the focused board first with the label 'this session', then the others newest first. The sketch is the later and more specific source.
3. The trigger count is hidden when total is 0, as the Phase 4 header count was.
4. The banner uses a yellow border and primary text without a fill, because the sketch fill needs `color-mix`. The Copy all open button is SDK `outline`, not accent, to keep the Phase 4 accent list.
5. The notice stays under the header hairline (Phase 4 position), not at the list bottom as in the sketch, because the Phase 4 notice component is reused unchanged.
6. The copied notice is one line and lasts 4000 ms, the Phase 4 notice duration. Only its title part truncates.
7. The copied notice always carries the full D-42 sentence, including `0 skipped, already on the board.` The `K not copied` clause shows only when K is above 0.
8. Row Copy shows on every top-level row, checked or not; subtasks copy through their parent.
9. Read-only rows keep chevron collapse and the subtask count, because they change the view only.
10. The short id is the last 6 characters of the root id.
11. Time labels are English, 24-hour, computed when the menu opens.
12. The menu refreshes on open, not on the poll, so the poll stays at one board call every 6000 ms.
13. Plain-language empty and error strings for the menu: `No other session has a board.`, `Could not load the session list. Reopen the list to retry.`, `This board is empty.`
