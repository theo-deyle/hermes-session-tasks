<objective>
Give the pane a session picker and the first read-only view: a picker row at the top that names the shown board, a menu that lists every board with its Hermes title, and a pick that shows another session's board read only.

Purpose: PANE-09 (D-43, D-44). Plan 06-06 adds Back, the focus rule, live updates and the edge states of the read-only view; plan 06-11 adds the copy buttons.

Planner decisions (record in the SUMMARY):
1. The pane stays one plain file over the 800 line soft ceiling (06-UI-SPEC Registry Safety decision; the SDK loads one uncompiled file and refuses a relative import). `MAX_PLUGIN_LINES` in tests/test_desktop_plugin.py moves from 800 to 1200 with that reason in a comment, so the file keeps a ceiling.
2. The harness walks the children of a `Button` after it records the button, so the trigger's title and count spans show in `nodes` and `lines`. Every existing pane test must stay green.
3. The harness gets a `calls` config key that calls named exports of the plugin and records `callResults`, so the pure helpers (time labels, title join, order) have direct tests. Until now the exports had no direct test.
4. `pane_rig._run_node` sets `TZ=UTC` for the node process, so time labels are the same on every machine.

Assumptions (RESEARCH, record in the SUMMARY): A7 (`Date.parse` takes the 6-digit fraction; a test settles it). RESEARCH Q2: `host.request('session.list')` works from a plugin pane; it is documented but no plugin calls it yet, so the live check in plan 06-11 is the proof and the fallback labels are the failure path.

Theme and SDK rules (PANE-13): imports only from `@hermes/plugin-sdk`, `react` and `react/jsx-runtime`; `jsx()` and `jsxs()` calls, no JSX; colours only as `var(--ui-*)` theme variables; `ctx.setTimeout` and friends. This plan integrates no external API.

Output: the picker, the menu, the first read-only view, the widened harness, tests/test_pane_picker.py.
</objective>
