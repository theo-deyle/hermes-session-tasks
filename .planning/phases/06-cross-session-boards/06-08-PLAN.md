<objective>
Let the agent list the sessions that have a board and read another session's board by session id: `board_sessions` and the optional `session_id` argument of `board_read`.

Purpose: TOOL-03 and TOOL-04 handlers (D-38, D-39). The schemas and descriptions come in plan 06-10. This plan changes the meaning of a `session_id` argument to `board_read`, so the tests that asserted the old meaning change here (RESEARCH Q6): `test_read_ignores_a_session_id_in_the_arguments` in tests/test_board_tools.py, and the `spoofed` expectation in tests/test_hermes_dispatch.py. The schema test in tests/test_tool_text.py changes in plan 06-10 with the schema.

Assumption RESEARCH A6 (record in the SUMMARY): 50 lines are enough for about five users' sessions; `more` counts the rest.

Flagged edge (unclassified probe item for TOOL-04, record in the SUMMARY): a cross read of a branch session id that never had a board makes the resolver copy its parent's board (Phase 1 D-06 fork rule), so that one read can create a board. This is the existing "one write a read may trigger" rule; this plan tests and accepts it.

Python matrix (CLAUDE.md): every Python test this plan adds must pass on 3.11 and on 3.14. Wave 3 runs with plan 06-09; the task verify commands name only this plan's files. This plan integrates no external API.

Output: the cross read path, `board_sessions`, their result helpers and tests.
</objective>
