<objective>
Ship the copy script that puts `plugin/desktop/plugin.js` on the Mac and the Windows PC, and the README steps for each machine.

Task 1 is the first end to end task of this plan: the script copies a file through `scp` into the Desktop plugin slot and prints its path and hash, run as `pwsh -File` from pytest with a fake `scp`. Task 2 adds the home rule per OS, the input guards, the dry run and the failure safety. Task 3 writes the README.

Purpose: DEV-05 and D-26. Desktop loads only a disk copy on the machine it runs on (RESEARCH Answer 5), and the devpc symlink delivers only the Python half. A wrong home on Windows installs into a folder Desktop never scans (RESEARCH Pitfall 4), so the home rule copies Desktop's own rule and is tested branch by branch.

Output: `scripts/install-desktop.ps1`, `tests/test_install_script.py`, `README.md`.

This plan runs on devpc only. Theo runs the script on the Mac in plan 03-07 and on the Windows PC in plan 03-08. Every script for Theo is PowerShell 7 (house rule 14).

Script layout (house rule: decide the map before code):
- `param()` block: `[string]$HermesHome = ''`, `[string]$DevpcHost = 'devpc'`, `[switch]$DryRun`.
- Constants: `$PluginId = 'hermes-session-tasks'`, `$RemotePath = '/home/theo/local_repo/hermes-session-tasks/plugin/desktop/plugin.js'`, `$TempName = '.plugin.js.new'`.
- `Resolve-HermesHome` - pure: takes every input as a parameter, so tests reach the Windows branch on Linux.
- `Get-DesktopHome` - reads the real environment and calls `Resolve-HermesHome`.
- `Test-DevpcHost`, `Copy-RemoteFile`, `Install-PanePlugin`, `Invoke-Main` (returns the exit code).
- Last line: `if ($MyInvocation.InvocationName -ne '.') { exit (Invoke-Main) }`, so a dot-source in a test defines the functions and runs nothing.
</objective>
