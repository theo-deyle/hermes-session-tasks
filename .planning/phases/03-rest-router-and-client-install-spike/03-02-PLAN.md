<objective>
Build the pane's board routes. One real path first: Hermes-style load of `plugin_api.py`, then `GET /board` reads what an agent tool wrote. Then the write and list routes with the D-22 reply shapes. Plan 03-04 adds `GET /meta`.

Purpose: API-01. The test pane (plan 03-06) and the real pane (Phase 4) read these exact shapes, so D-22 and D-23 are fixed here. The thin router keeps all logic in core, where the layout guards and the coverage gate reach it.

Why: the first end to end task needs the manifest, the router, two small core modules, the warning config and a host-style load test. Output: the dashboard manifest and router, `board_json.py`, `board_api.py`, `BoardStore.list_boards`, and the route tests.

Module map (house rule: decide the map before code). Each new core module stays under 200 lines.
- `plugin/dashboard/plugin_api.py` - FastAPI only: `load_core`, `core_module`, `get_api`, `EditBody`, four plain def handlers that map an `ApiReply` to a `JSONResponse`.
- `plugin/session_tasks/board_json.py` - `Board` and `Item` to JSON dicts. Pure.
- `plugin/session_tasks/board_api.py` - the request logic: resolve, delegate check, parse, apply, map outcomes to `ApiReply(status, body)`. It never raises for a request fault, so the router needs no isinstance check across the two module trees (RESEARCH Pattern 2 consequence).

Restart rule (CONTEXT): any edit to `plugin_api.py` needs a restart of every `hermes serve` process, and the restart is announced before it happens, because it drops live Desktop connections. This plan restarts nothing. The announced Desktop restarts in plans 03-08 (Mac) and 03-10 (Windows PC) load the final code after every code plan is done.
