<objective>
Build the test pane: one plain ESM file that reads a board through the routes, shows whether `board.updated` arrived, runs a write test, and shows a version banner. Then the DEV-03 checks and the version drift test.

Task 1 is the first end to end task of this plan: the pane, run in a node VM harness, reaches the real router through a loopback relay and renders the board. Task 2 adds the event lines, the poll, the write test button and the banner. Task 3 adds the syntax check, the import allowlist, the text and colour bans, and the drift test.

Purpose: success criteria 2 to 5, and the file that plans 03-07 and 03-08 install on the Mac and the Windows PC. A mismatch between the pane's request shapes and the router shows up here, before Theo touches a machine.

Output: `plugin/desktop/plugin.js`, the harness, the relay, `tests/test_desktop_plugin.py`, and the drift tests in `tests/test_version.py`.

Pane layout, one line per element, in this order:
1. `backend {backend_version}, api {api_version}`, or `backend not reached`
2. `pane {PLUGIN_VERSION}, api {API_VERSION}`
3. `Version mismatch: update the desktop plugin on this machine` (only on a mismatch)
4. `session {sid}, board rev {rev}`, or `no session focused`
5. `agent event: rev {N} at {HH:MM:SS} ({this chat|other chat})`, or `agent event: none yet`
6. `pane event: ...` in the same form, for actor user
7. `write test: add ok at rev {N}, stale write answered {error} ({reason}) at rev {M}`, or `write test: not run`
8. One line per item: `[ ]` or `[x]`, a space, `#{id}`, a space, the text; a subtask line starts with two spaces; `board is empty` when there are no items
9. A `Button` labelled `Run write test`

In replies to Theo, call this pane "the test pane" (house rule 22).
