# Phase 4 - UI Design Contract

> Visual and interaction contract for the Session tasks pane. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Locked inputs: D-30 to D-34 in `04-CONTEXT.md` and PANE-13 in `REQUIREMENTS.md`. This file adds no decision that contradicts them.

The pane is the only screen. It has one empty state, one notice line and one confirm dialog.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no `components.json`, no shadcn, no design system file in this repo; none is created) |
| Preset | not applicable |

## Spacing Scale

All values are multiples of 4px. The pane styles layout with inline `style` objects that carry these values. It uses no Tailwind class (see Color).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between chevron, checkbox and text. Vertical padding of a row. |
| sm | 8px | Gap between the header title and the copy button. Gap above the add line. |
| md | 12px | Pane padding on all four sides. Header padding. |
| lg | 24px | Subtask indent. Chevron column. Icon button size. Checkbox hit area. |

Exceptions (each one sets a size the SDK does not set):

| Item | Value | Reason |
|------|-------|--------|
| Pane width | 320px | Fixed by D-30 context and the Phase 3 registration (`width: '320px'`). |
| Subtask indent | 24px | Equals the chevron column, so a subtask checkbox sits under its parent checkbox. |
| Checkbox hit area | 24px square | The SDK box is 16px. A 24px wrapper centres it and takes the click. |
| Row minimum height | 32px | 24px control plus 4px padding above and below. |
| Divider | 1px | One hairline under the header. |

Row layout, left to right:

1. Top-level row: chevron column 24px (empty when the item has no subtasks), checkbox hit area 24px, text (flexible, wraps), subtask count (only when the item has subtasks), plus button 24px, trash button 24px.
2. Subtask row: 24px indent, checkbox hit area 24px, text (flexible, wraps), trash button 24px. A subtask has no plus button and no chevron (two levels only, D-01).
3. The plus and trash buttons keep their space at all times. They change from hidden to visible. The row never reflows on hover.

## Typography

The pane sets two sizes. Both equal the Desktop defaults for the components used. The pane sets them through inline `style` (`fontSize`, `fontWeight`, `lineHeight`) because no Tailwind class is allowed.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Row text, input text, notice, subtask count, empty state description | 12px (0.75rem) | 400 | 16px (1.33) |
| Header "N of M open", empty state title | 14px (0.875rem) | 500 | 20px (1.43) |

- Two weights only: 400 and 500.
- Row text and `Input` text share 12px, so a row does not change size when it enters edit mode.
- A long item text wraps (`overflowWrap: 'anywhere'`, `whiteSpace: 'pre-wrap'`). An item never truncates with an ellipsis.
- Done text uses `textDecoration: 'line-through'`. Weight and size do not change.

## Color

PANE-13 applies. Colour comes only from Hermes theme variables, set through inline `style`. No hex, no `rgb()`, no named colour, no Tailwind class, no custom palette, no `color-mix`.

Theme variables the pane uses (and nothing else):

| Variable | Used for |
|----------|----------|
| `var(--ui-text-secondary)` | Done item text. Header "N of M open". Subtask count. Notice line. |
| `var(--ui-text-tertiary)` | Idle chevron, idle plus and trash icons. |
| `var(--ui-stroke-secondary)` | The hairline under the header. |

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Desktop editor background. The pane leaves the background alone (SDK rule). | Whole pane surface. |
| Secondary (30%) | `var(--ui-stroke-secondary)` and the SDK ghost button hover fill | Header hairline. Hover fill on icon buttons. |
| Accent (10%) | SDK-owned. The pane writes no accent colour of its own. | Checked fill of `Checkbox` and the focus rings of `Input` and `Button`. |
| Destructive | SDK-owned through `ConfirmDialog destructive` | The Delete button in the one confirm dialog. The trash icon is not red. |

Accent reserved for: the checked state of the item `Checkbox` and the SDK focus ring. Nothing else.

Rules:

1. Open item text inherits the Desktop foreground colour. The pane sets no colour on it.
2. A checked item is muted by two cues together: line-through and `var(--ui-text-secondary)`. Do not move it and do not hide it (D-33).
3. The SDK components read other theme variables inside themselves (for example the ghost button hover fill). Those are not pane code and need no listing.
4. The Phase 3 test `test_plugin_has_no_colour_literal` stays and keeps passing. Add a check that the source holds no Tailwind colour class and no `className` string at all.

## Interaction Contract

The rules below restate D-30 to D-34 and add only the detail the executor needs. Where a line says "(D-xx)", the CONTEXT.md text wins.

### Header (PANE-11, D-33)

1. Left: `{open} of {total} open` at 14px, weight 500, `var(--ui-text-secondary)`.
2. Right: `CopyButton` icon. It copies the whole board as a markdown checklist. It is disabled when the board is empty.
3. Markdown format: one line per item in board order. Top level: `- [ ] text` or `- [x] text`. Subtask: two spaces of indent, then the same. No item ids (D-05). A text that starts with `#<digits>` gets one leading backslash, the same rule as `plugin/session_tasks/markdown.py`.
4. A 1px `var(--ui-stroke-secondary)` hairline sits under the header.
5. The notice line sits under the hairline (see Notice line).

### Add an item (D-30, PANE-04)

1. One `Input` with placeholder `Add an item` always sits after the last row, inside the `ScrollArea`. It does not pin to the pane bottom.
2. Enter trims the text. An empty result does nothing. Otherwise the pane adds the item at once, clears the line, and keeps focus in the empty line.
3. Escape clears the line. Blur keeps the typed text and does not save.
4. After an add, the list scrolls so the add line stays visible.
5. The item shows at once, before the reply (D-34). Until the reply arrives, its controls do nothing, because it has no id yet.

### Add a subtask (D-30, PANE-06)

1. A `Plus` icon button shows on hover or keyboard focus of a top-level row only. Subtask rows have none.
2. Click opens a subtask add line directly under the last subtask of that item, indented 24px, with placeholder `Add a subtask`. It takes focus.
3. If the parent is collapsed, the click expands it first.
4. Enter, Escape and the optimistic add work as in the main add line. The line stays open after Enter for the next subtask.
5. Escape closes the line. Blur with empty text closes it. Blur with typed text leaves it open.
6. Only one subtask add line is open at a time. Opening another closes the first if its text is empty, else leaves both (the pane keeps the typed text).

### Edit the text (D-31, PANE-05)

1. A click on the item text replaces it with an `Input` holding the same text, focused, caret at the end. Row height does not change for a one-line text.
2. Enter saves. Escape cancels and restores the old text. A click elsewhere (blur) saves.
3. Saving unchanged text sends nothing. Saving empty text cancels the edit (restores the old text). It never deletes the item.
4. The checkbox stays clickable in edit mode. A mouse press on it does not take focus from the `Input` (call `preventDefault` on `mousedown` of the hit area), so the edit stays open and the typed text stays.
5. Starting a second edit saves the first through blur. At most one row is in edit mode.
6. A done item can be edited too.

### Check and uncheck (D-34, PANE-03)

1. A click on the checkbox flips it at once and sends `set_checked` with `base_rev`.
2. On a stale reply the pane takes the returned board and retries the same op once on the new revision, if the item still exists. The retry sends the new `rev` as `base_rev`.
3. A checked item stays in place, struck through, muted (D-33). It does not move and does not hide.
4. A parent and its subtasks check independently. The pane never checks one from the other. The parent row shows the `{done}/{total}` count instead.

### Collapse (PANE-02, Claude's Discretion)

1. A parent row with subtasks shows a `ChevronDown` (open) or `ChevronRight` (collapsed) button in the 24px chevron column.
2. Default is expanded. State lives in the pane only, keyed by item id. It resets when the focused session changes. It is never stored.

### Delete (D-32, PANE-07)

1. A `Trash2` icon button shows on hover or keyboard focus of any row.
2. An item with no subtasks is deleted at once with a `remove` op. There is no confirm and no undo.
3. An item with subtasks opens `ConfirmDialog` with the copy in Copywriting. Confirm sends `remove`. Cancel does nothing. The count is all subtasks, checked or not.
4. The dialog is the SDK one. Enter confirms and Esc cancels, as the SDK sets.

### Hover and focus reveal

1. Hover state lives in React state (`onMouseEnter`, `onMouseLeave`). Keyboard focus inside a row (`onFocus`, `onBlur` on the row) reveals the same buttons. No CSS hover class is used.
2. Hidden buttons use `visibility: 'hidden'`, so they keep their space and leave the tab order. Visible buttons are tabbable.

### Live update and poll (PANE-08, PANE-01)

1. `ctx.onEvent('plugin.hermes-session-tasks.board.updated', ...)` triggers a reload of the focused board. The 6000 ms poll (`POLL_MS`) stays as the fallback. Both are kept from the Phase 3 pane.
2. A reload never resets an open edit `Input`, an add line, or the collapse state.
3. A reply with a revision lower than the one shown is ignored. While a write is in flight, reload replies are ignored and the write reply wins.
4. If the item under edit is gone from the new board, the edit closes and the stale notice shows.
5. When the focused session changes, the pane drops edit and add state, then loads the new board.

### Stale write (D-34)

1. Writes are optimistic and carry `base_rev`. A stale reply (HTTP 200, `ok: false`, `error: "stale"`, with the board) replaces the shown board.
2. A check or uncheck retries once (see above).
3. An add or a text edit is not retried. The typed text goes back into the `Input` it came from (the add line, the subtask add line, or the edit `Input`), so Theo presses Enter again.
4. The stale notice shows for 4000 ms.
5. A thrown error (any other failure) reloads the board, restores typed text the same way, and shows the write failed notice.

### Notice line

1. One line, 12px, `var(--ui-text-secondary)`, directly under the header hairline. It truncates with an ellipsis (`whiteSpace: 'nowrap'`, `overflow: 'hidden'`, `textOverflow: 'ellipsis'`) and never wraps.
2. It shows one message at a time. Priority: version mismatch, then write failed, then stale, then load failed.
3. Stale and write failed clear after 4000 ms with `ctx.setTimeout`. Load failed clears on the next good reload. Version mismatch stays while the mismatch holds.
4. It takes no space when empty.

### Registration

Keep the Phase 3 registration with the name and title changed: `ctx.register({ id: 'pane', area: 'panes', title: 'Session tasks', data: { placement: 'right', dock: { pane: 'workspace', pos: 'right' }, width: '320px' }, render })`. Change the plugin `name` from `Session tasks (test)` to `Session tasks`. Remove the `Run write test` button and the diagnostic lines.

## UI Considerations

Applicable state considerations resolved: 7 covered, 2 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | item list | ✅ covered | An empty board shows `EmptyState` (`The agent adds items here.` / `Add one below.`) with the add line under it. The header count is hidden and the copy button is disabled. |
| empty | no focused chat | ✅ covered | With no focused session the pane shows `EmptyState` with `Open a chat to see its items.` and no add line. |
| error | board load, write | ✅ covered | The notice line carries `Could not load the board. Retrying.` and `Could not save that change. Try again.` The poll retries a failed load. |
| partial | parent with collapsed subtasks | ✅ covered | The chevron shows `ChevronRight` and the `{done}/{total}` count stays visible on the parent row. |
| zero-one-many | delete confirm | ✅ covered | The description reads `1 subtask` for one and `{n} subtasks` for more. An item with zero subtasks never opens the dialog. |
| long-text | item text, 500 characters | ✅ covered | Text wraps with `overflowWrap: 'anywhere'` and never truncates. `Input` has `maxLength` 500. |
| populated | done items | ✅ covered | A checked row stays in place with line-through and `var(--ui-text-secondary)`. |
| overflow | 100 items (`MAX_ITEMS`), long list | 🧪 backstop | `ScrollArea` scrolls the list. At 100 items the backend rejects an add and the notice shows the write failed copy with the typed text restored. A pane test adds an item to a full board and checks both. |
| overflow | 320px width with plus and trash visible | 🧪 backstop | At 320px a top-level row keeps about 180px for text. A VM harness test with a 500 character text and a live Mac check confirm the row wraps and does not push the buttons out. |
| concurrent | add line typed while a stale add restores its text | ⚠ unresolved | Planner assumption: writes from one pane run one at a time. A stale add restores its text to the line only when the line is empty. When the line holds newer text, the restored text goes in front of it, joined by a space. Rare at about five users. |

## Defaults Chosen By This Spec

These values were not fixed by CONTEXT.md or REQUIREMENTS.md. The spec took the SDK default or the closest fit.

1. Two type sizes (12px and 14px) and two weights (400 and 500), taken from the SDK control and text defaults.
2. Done text colour is `var(--ui-text-secondary)`. D-33 asks only for "a muted colour".
3. No Tailwind class anywhere. The Phase 3 pane used Tailwind layout classes and the `text-(--ui-text-secondary)` form. This spec replaces them with inline `style`, so the PANE-13 colour rule is literal and no layout depends on a class that Desktop may not compile for a disk plugin.
4. Subtask count `{done}/{total}` on a parent row. REQUIREMENTS.md "Out of Scope" says to show a count instead of auto-checking a parent.
5. Blur on the add line keeps the text and does not save. D-30 names only Enter and Escape.
6. A no-chat state with the copy `Open a chat to see its items.`, shown through the same `EmptyState`.
7. The write failed and load failed notices, which D-34 does not name.
