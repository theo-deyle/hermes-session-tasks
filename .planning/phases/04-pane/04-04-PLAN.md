Stale rule (plugin/session_tasks/revision.py `is_stale`): an op is stale when its target item has `rev > base_rev`, or `base_rev > board rev`; a parent remove is also stale when a subtask changed. A top-level add is never stale. A missing target is not stale; the store answers `invalid` (not_found) for it.

Harness (plan 04-02): steps `check`, `outside`, `event`, `timers`; config `restSequences`, `duringWrite`; output `atWrite`, `timeouts`, `nodes`, `checkboxes`. Rig helpers: `posts`, `board_gets`, `checkbox`, `stale_body(board, root_id)`.

New contracts (plugin/desktop/plugin.js):
- constants `NOTICE_MS = 4000`, `STALE_NOTICE = 'Board changed, showing the latest'`, `WRITE_FAILED_NOTICE = 'Could not save that change. Try again.'`, `LOAD_FAILED_NOTICE = 'Could not load the board. Retrying.'`
- `viewBoard(board, pendingOps)`: the board with each op applied in order through `applyOp`; never mutates
- `writeOutcome(reply, op, retried)`: returns `'ok'`, `'retry'`, `'stale'` or `'failed'`
- `noticeText({ meta, notice, loadFailed })`: returns one of the four strings or null
- `Notice({ text })`: stateless; renders nothing for null
- inside `Pane`: `sendOp(op, onOutcome)` starts a write and returns nothing; `onOutcome(outcome)` is called once with `'ok'`, `'stale'` or `'failed'` after the write settles (plans 04-06 and 04-07 use it to clear or restore typed text)
