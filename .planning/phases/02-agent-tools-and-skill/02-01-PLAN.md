Module map for the whole phase (house rule: decide the map before code). Every new core module stays under 300 lines.

- `plugin/plugin.yaml` - Hermes manifest.
- `plugin/__init__.py` - entry point; re-exports `register` only.
- `plugin/session_tasks/wiring.py` - `register(ctx)`: builds the store, resolver and handlers, registers tools, hooks, prompt section and skill.

- `plugin/session_tasks/results.py` - JSON result strings for read, write, stale and error.
- `plugin/session_tasks/board_tools.py` - `BoardTools`: the `board_read` and `board_edit` handlers.
- `plugin/session_tasks/edit_args.py` - parse raw or coerced `board_edit` arguments into ops (plan 02-02).

- `plugin/session_tasks/hooks.py` - `pre_tool_call` guard and `post_compaction` callbacks (plan 02-02).
- `plugin/skills/board-rules/SKILL.md` - the bundled skill (plan 02-03).

`register` lives in core `wiring.py`, not in `plugin/__init__.py`, so tests import it with no package trick, coverage counts it, and the layout guards scan it. This choice is Claude's discretion under CONTEXT ("`__init__.py` registration").
