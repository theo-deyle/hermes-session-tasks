<objective>
Build the argument parser for board_edit and the hard guard, as pure core code plus two small hook callbacks.

Task 1 writes `edit_args.parse`, the one parser that the pre_tool_call hook and the board_edit handler share (RESEARCH Pattern 2, Finding 2). Task 2 writes the guard rule (`guard.py`) and the two hook callbacks (`hooks.py`). Plan 02-04 registers the hooks and calls the parser from the handler.

Purpose: the guard must see raw model arguments, and it must never break other tools. Both risks are settled here with tests that need no gateway.

Output: `edit_args.py`, `guard.py`, `hooks.py` and their tests. This plan runs in parallel with plan 02-03; the two plans share no file.

Discretion recorded here (reversible): the hook blocks a board_edit call whose arguments do not parse. Hermes coerces arguments after the hook runs, so a parse the hook allowed on failure could pass a guarded op that Hermes later repairs. Blocking on a parse failure closes that gap. The block text is the same rule text the handler would return.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model to pre_tool_call hook | The hook sees raw model arguments before Hermes coerces them. They are untrusted. |
| hook to every Hermes tool | The hook fires for every tool call in the session. A fault in it can block all tools. |
| Hermes compaction to post_compaction hook | Session ids come from Hermes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Tampering | hooks.pre_tool_call, edit_args.parse | high | mitigate | One parser serves the hook and the handler. It accepts every form Hermes repairs (JSON-string ops, bare object, digit strings, true or false strings). A call the parser rejects is blocked, so a guarded op cannot reach the handler through a coercion difference. |
| T-02-05 | Denial of Service | hooks.pre_tool_call | high | mitigate | First statement returns None for any other tool name. The board path sits in try/except and fails closed for board_edit only. A test with a broken service proves other tools pass. |
| T-02-06 | Denial of Service | edit_args.parse | medium | mitigate | `MAX_OPS = 100` per call. The store caps a board at 100 items and runs one BEGIN IMMEDIATE per call. |
