<objective>
Install the plugin on devpc and measure the agent behaviour with the real model, then announce the gateway restart.

Task 1 links and enables the plugin with the Hermes CLI. Task 2 runs the headless live protocol from RESEARCH ("Live test protocol", steps 1 to 4): Claude runs every prompt with `hermes chat --oneshot --format stream-json`, reads the stream and data.db, and records the call rate. Each headless run is a new process, so it loads the plugin with no gateway restart. Task 3 stops for the restart announcement, because the restart in plan 02-06 drops every live Desktop connection (project rule: announce the restart before it happens).

Purpose: success criterion 4 (5 of 5) and the live half of criterion 5 depend on model behaviour. RESEARCH Finding 1 says plugin tools are deferred; the prompt section from plan 02-03 is the fix, and this plan measures it. A rate under 5 of 5 goes to Theo as one cost question about `tools.tool_search.enabled: off`. It is never a task here.

Output: no repo file changes. The SUMMARY holds the enable output, the toolset check, the per-run table (session id, board_edit calls, items on the board, todo_list calls, first line of the final reply) and the rate.

Known effect, recorded for the Phase 3 discuss step: once the plugin is enabled, an agent write in any live Hermes session changes the real `~/.hermes/plugin-data/hermes-session-tasks/data.db`. The real-home session guard in tests/home_guard.py fails a pytest run during which that file changes. A `./scripts/check.sh` run can then fail with "real Hermes home gained" while Theo uses Hermes. This plan changes no test code; the SUMMARY records the effect.

Undo for the whole plan: `hermes plugins disable hermes-session-tasks`, then remove the symlink `~/.hermes/plugins/hermes-session-tasks` (the symlink only, never its target).
</objective>

7. ask-a (new session): "Add 'call the glass supplier' to my board."
8. ask-b (resume ask-a): "Remove the glass supplier item from my board."
9. ask-c (resume ask-a): "Yes, remove it."
10. finish-a (new session): "Add 'count the dataclasses in plugin/session_tasks/model.py' to my board."

Pass rules:
- list-1 to list-5: each run has at least one board_edit call and its board holds the listed items. Rate = passing runs of 5, a whole number. 5 of 5 passes success criterion 4.
- own-job: zero board_edit calls.
- ask-b: the glass supplier item is still on the board after the run, and the final reply holds a question to Theo. ask-c: the item is gone, and the stream shows a board_edit call with confirmed true.
- finish-b: the item is checked on the board, and the reply has one line that says the item is checked or done.

When no run calls the board at all, the tools are not reaching the model: stop the round, check that the session prompt holds the section `hermes-session-tasks.board-rules` and that the toolset is on, and report the finding (standing rule: a broken system stops the test round). A rate between 1 and 4 of 5 is a measurement, not a broken system: record it, change no setting, and put one plain cost question for Theo in the SUMMARY about `tools.tool_search.enabled: off` (it loads every tool schema into every session, so each session costs more tokens). Write the per-run table and the rate into the SUMMARY. Quote at most the first line of a reply; never copy a raw stream into the repo.
