<check_script>
Tasks 2 and 3 run one check script, `desktop_check.py`, in the session scratchpad. Claude writes it in Task 2. It is never committed. Run it as `timeout 60 ~/.hermes/hermes-agent/venv/bin/python -I <script> <mode> <argument>`. Rules for every mode:
- Put `~/.hermes/hermes-agent` on sys.path and open state.db only through `SessionDB(read_only=True)` from `hermes_state`. Find the session listing method, `get_messages`, `get_compression_lineage` and the column that holds the stored system prompt in the read_first files.
- Open `~/.hermes/plugin-data/hermes-session-tasks/data.db` only with sqlite3 in read-only URI mode (`file:<path>?mode=ro`, `uri=True`). The root of a session is its row in the aliases table, else the session id itself.
- Print one JSON object and never print prompt text or full replies: at most the first line of a reply.
Modes:
1. `added <restart time>`: find the newest session with source desktop that started after the restart time. Report `session_id`, `section_present` (the stored system prompt holds `hermes-session-tasks.board-rules` and the first line of PROMPT_SECTION_TEXT), `root`, `rev`, `items` (id, text, checked, updated_by) and `reply_first_line` (the last assistant message). Exit 1 when `section_present` is false or the board holds fewer than 3 items.
2. `compressed <session id>`: report `lineage` from `get_compression_lineage(session_id)`, `newest_id` (the newest id of that lineage; with `compression.in_place` true it equals the session id), `newest_root`, `rev` and `items`. Exit 1 when `newest_root` differs from the root of the session id or the items differ from the `added` result.
</check_script>
