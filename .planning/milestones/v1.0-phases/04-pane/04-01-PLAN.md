Routes (plugin/dashboard/plugin_api.py, plugin/session_tasks/board_api.py):
- `GET /meta` returns `{ok: true, plugin_id, backend_version, api_version}`.
- `GET /board?session_id=` returns `{ok: true, session_id, root_id, rev, board: {root_id, rev, forked_from, items: [{id, parent_id, position, text, checked, rev, updated_by, created_at, updated_at}]}}`. Items arrive in display order: each subtask after its parent.
- `POST /board/edit` body `{session_id, ops, base_rev}` (extra keys answer 422). Replies, all HTTP 200: `{ok: true, root_id, rev, summary, changed_ids, board}`; `{ok: false, error: 'stale', reason, op_index, item_id, message, root_id, rev, board}`; `{ok: false, error: 'invalid', op_index, rule, message}` (no board). A blank or unknown session answers HTTP 400, which `ctx.rest` turns into a thrown error.

Ops (plugin/session_tasks/edit_args.py, OP_FIELDS):
- `{op: 'add', text, parent_id?}` (the parser also takes `checked` and `parent_ref`; the pane never sends them)
- `{op: 'set_checked', item_id, checked}`
- `{op: 'set_text', item_id, text}`
- `{op: 'remove', item_id}`
- `base_rev` is required when an op targets an existing item. The pane sends `base_rev` on every write.
