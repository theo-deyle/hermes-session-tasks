<objective>
Build the copy in the board store: one write transaction that reads the source board and the target board, plans the copy with pure rules, adds the items to the target, and journals where each copy came from. The agent tool (plan 06-05) and the pane route (plan 06-09) both call this one method.

Purpose: TOOL-05 and PANE-10 core. The copy rules D-40, D-41 and D-42 live in one pure module; the transaction and the journal live in the store.

Python matrix (CLAUDE.md): every Python test this plan adds must pass on 3.11 and on 3.14. Plans 06-01 to 06-04 run in the same wave, so a red test of another plan can show in a full run; the task verify commands name only this plan's files. `./scripts/check.sh` runs at the end of the wave (see verification).

Planner decisions on gaps CONTEXT leaves open (record each in the SUMMARY as an assumption, not as a fact):
1. RESEARCH A1: a skipped parent skips its subtasks, and each counts as skipped.
2. RESEARCH A2: a text planned earlier in the same batch counts as open for later items.
3. RESEARCH A3: in "all open", an open subtask under a checked parent copies as a top-level item.
4. RESEARCH A4: an unknown id in item_ids rolls the whole copy back and names that id.
5. RESEARCH A10 and Open Question 1: one `copied` journal row per copied item. A 100 item copy writes 200 journal rows and the prune keeps 100; the Phase 5 pointer line covers the gap.
6. Planner addition: a copy onto the same root raises SameBoard in the store as well as in the callers (defense in depth).

No schema change: `changes.op` is `TEXT NOT NULL` with no CHECK, so `SCHEMA_VERSION` stays 1. This plan integrates no external API.

Output: copy_plan.py, the copy types in model.py, BoardStore.copy_items, two new test modules.
</objective>
