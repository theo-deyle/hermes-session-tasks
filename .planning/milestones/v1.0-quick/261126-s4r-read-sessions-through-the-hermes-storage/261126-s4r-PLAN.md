# Quick task 261126-s4r: read sessions through the Hermes storage interface

## Why

On a gateway with a newer Hermes (canary after v0.23.4), `board_read` and the pane fail with `AttributeError` at `lineage.py` line 173: `hermes_state.SessionDB has no attribute 'is_explicit_fork_child'`.

Hermes moved session storage behind `persistence_assembly`. `hermes_state.SessionDB` is now a stand-in that carries only the methods its plugin guide lists. It lacks three of the six methods the plugin uses: `is_explicit_fork_child`, `get_compression_lineage` and `get_session_title`. Hermes removes the stand-in no earlier than v0.27.0.

## Task 1: tests

File: `tests/test_adapters.py`

- With a fake storage interface, `open_session_reader` returns a reader that maps the six methods to the store handle and closes it once.
- A missing store raises `sqlite3.OperationalError` and opens nothing.

## Task 2: the adapter

File: `plugin/session_tasks/session_reader.py`

- Import `persistence_assembly` first. On `ImportError`, use `SessionDB(read_only=True)`.
- `_StoreReader` maps: `get_session` to `store.sessions.get(...).as_session_row()`, `get_compression_lineage` to `store.lineage.lineage`, `is_explicit_fork_child` to `store.lineage.is_fork_child`, `get_session_title` to the `title` of the session row, `get_messages` to `store.messages.read_transcript`.
